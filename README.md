# Предсказание цен на автомобили
Данный репозиторий является решением HW1

# Выводы о проделанной работе:
## 1. Что было сделано

### 1.1 EDA
- Обнаружение пропущенных значений и дубликатов
- Анализ распределений числовых и категориальных признаков
- Выявление выбросов и аномальных значений
- Исследование корреляций между признаками

### 1.2 Предобработка данных
- Преобразование типов данных
- Заполнение пропусков медианными значениями
- Удаление дубликатов
- Масштабирование числовых признаков с помощью StandardScaler
- One-hot encoding категориальных признаков
- Генерация новых признаков на основе имеющихся
- Обработка выбросов методом межквартильного размаха

### 1.3 Обучение моделей
- Разделение данных на обучающую и тестовую выборки
- Обучение нескольких моделей для сравнения:
  - Линейная регрессия
  - Ridge
  - Lasso
  - ElasticNet
- Подбор гиперпараметров c кросс-валидацией при помощи GridSearchCV 

### 1.4 Разработка Streamlit приложения
- Создание веб-интерфейса:
  - EDA с визуализациями
  - CSV Prediction для группового предсказания
  - Form Prediction для единичного предсказания
  - Model Information с информацией о модели и полученными метриками

## 2. Результаты

### 2.1 Метрики лучшей модели
**Модель: Ridge**

| Метрика | Обучающая выборка | Тестовая выборка |
|---------|-------------------|------------------|
| **MSE** | 66,769,764,039 | 129,572,071,254 |
| **R²**  | 0.767 | 0.775 |

### 2.2 Интерпретация результатов
- **R² = 0.775** на тестовой выборке означает, что модель объясняет 77.5% дисперсии цен
- Модель везде показывает небольшую разницу между train и test R², что может говорить о хорошей обобщающей способности, однако огромные веса модели заставляют задуматься о переобучении

## 3. Что дало наибольший прирост качества
- Наибольший прирост качества дало добавление категориальных признаков в модель с использованием One-hot encoding, применение Ridge вместо обычной линейной регрессии также улучшило качество

## 4. Что не удалось сделать и почему

- Полная обработка текстового поля name, не увидел общего правила и получалось много категорий
- Полная обработка признака torque, очень сложный формат данных, из-за чего, веротяно, в данные попало много мусора
- Отнормировать данные для стримлита и добавить медиану в pickle файл, передавал медиану словарём и scaler, медиана считывалась всегда пустой, а scaler как-будто не сохранял все признаки, пришлось убрать на итоговой модели

## 5. Оценка разработанного сервиса
- Приложение имеет интуитивно понятный и визуаьно приятный интерфейс, есть разделение на чёткую структуру, выбор загрузки данных для предсказания, вывод метрик и анализ исходных данных, использовать удобно
- Были визуализированы распределения всех признаков, box-plot для анализа аномальных значений, распределение целевой переменной, таблица корреляций и важность признаков, но только на исходных данных, что делает визуальный анализ менее полным
- При загрузке данных и ручном вводе могут возникать ошибки обработки из-за некорректных значений
- В качестве дальнейшей работы можно рассмотреть отображение анализа вводимых данных, улучшение предобработки некоторых полей, применение более сложных моделей, доработку самого пользовательского интерфейса
